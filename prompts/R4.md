Read `~/Literary-Heritage-Archive/PLAN.md` (D12, D15, §3.3, §5 R4) and

## R4-A — Sync protocol

**Context:** decision D12: hybrid logical clocks, field-level last-writer-wins,
tombstones, server as arbiter; CRDT explicitly deferred. R3-B already writes an
HLC oplog locally.

**Task (split first, then build — simulation before wire, wire before UI):**
1. **Simulation suite first:** a pure-TS sync core in `packages/sync` exercised by
   tests simulating 2–3 virtual devices: concurrent field edits, create/delete
   races, schema changes mid-sync, clock skew, interrupted syncs, tombstone
   resurrection attempts. Every scenario asserts convergence + no silent data loss
   (LWW-losing values must land in the activity log).
2. Wire protocol: authenticated batch push/pull endpoints (Laravel), per-database
   scope, resumable cursors; blob sync by content hash.
3. Client integration: sync engine driving the local driver's oplog; conflict
   surfacing UI only for true concurrent-field conflicts; background-safe on
   desktop, **foreground sync on mobile** (deferred list: background sync).
4. Compaction: tombstone + activity-log retention policy.

**AC:** simulation suite green incl. adversarial scenarios; two real devices +
server converge in manual test; docs/SYNC-PROTOCOL.md versioned.

## R4-B — Accounts, registration toggle, sharing, compliance

Depends: R4-A (accounts exist to sync).
**Task (split first, then build):**
1. Registration with **instance-level open/closed toggle** (admin setting; closed
   instances still allow invites) — the family instance runs closed.
2. Device linking (a local database opts into sync under an account); email
   verification + password reset — pick and wire an SMTP path (env-configurable;
   also used by R4-C email backups).
3. Workspace membership + roles activate (the P30 groundwork from R1-B1): owner /
   editor / viewer per database; API policies enforce.
4. Compliance: **account deletion** (full cascade + blob cleanup; export offered
   first via the R3-C vault) — Apple requirement + Québec Law 25/GDPR; privacy
   policy page; storage **quotas** per account; rate limiting + upload scanning.

**AC:** policy tests per role; deletion leaves zero user data (verified by sweep);
registration toggle honored incl. invite path; quota enforcement tested.

## R4-C — Backup destinations

**Context:** P27 adopted + expanded. Distinct from the R3-C vault (which is the
local format): this is *pushing* backups somewhere else, from the UI, on schedule.

**Task (split first, then build):**
1. Backup artifact = the vault zip (+ SQLite) of selected databases.
2. Destinations, pluggable (registry pattern like field types): **SFTP**, **WebDAV**
   (covers Nextcloud et al.), **email** (size-guarded, uses R4-B SMTP). **Proton
   Drive: best-effort** — no official public API; investigate rclone/bridge and
   report feasibility before building; do not block the epic on it.
3. Scheduling (server instances: queue/cron; desktop: app-scheduled), retention
   (keep-last-N), backup history UI with outcome per run.
4. **Restore path tested** — a backup that can't restore is not a backup: restore =
   vault re-import (R3-C) + verification report.

**AC:** each destination round-trips (backup → wipe → restore → parity check);
scheduled run observed; failure alerting (in-app + email) on a broken destination.

## R4-D — Hosting & operations

**Context:** decision D15: hosted instances live on cPanel shared hosting for now
(PostgreSQL confirmed available; no docker, no long-running workers). AGPL-3.0.

**Task (split first, then build):**
1. **Shared-hosting deployment mode:** documented install for cPanel — plain PHP
   deploy of `apps/api` + built client assets, Postgres setup, queue via cron
   (`schedule:run` + database queue driver), storage paths, HTTPS notes. This is
   also the family-instance install guide (registration closed). May be pulled
   forward as soon as R1 is usable — coordinate with the user.
2. Standard deployment: docker compose production profile for VPS self-hosters
   (AGPL public release includes both paths).
3. Monitoring: self-hostable error reporting (GlitchTip/Sentry) wired API + client;
   uptime/queue-health checks appropriate to shared hosting.
4. **Platform self-backup** (distinct from user backups): Postgres dumps + blob
   storage backup, restore-tested.
5. Public release checklist: AGPL headers/NOTICE, README, screenshots, security
   audit of `.env`/secrets, product branding = **Heritage Archives Patrimoine
   (HAP)** (D13 ✅), announce.

**AC:** family instance deployed on the real cPanel host and used; VPS path
verified on a throwaway box; monitoring captures a forced error end-to-end;
public repo released after user go.
