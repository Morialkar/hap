## R0-S1 — v2 Docker time capsule

You are working on the Literary Heritage Archive project. Read
`~/Literary-Heritage-Archive/PLAN.md` (§1, §2) first.

**Context:** `~/Eusebe` contains a Laravel **3** app (2012, pre-Composer, framework
vendored in `laravel/`, app code in `application/`). It cannot run on modern PHP
(needs ~5.3–5.6). We need it running reproducibly in Docker so a characterization
test suite can be written against it. **`~/Eusebe` is strictly read-only** — mount it,
never modify it.

**Task:** Create `~/Literary-Heritage-Archive/legacy/` containing:
- `compose.yml`: a `php:5.6-apache` service serving the app (mount `~/Eusebe` read-only;
  docroot is `public/`; Laravel 3 needs `mod_rewrite` and the `mysql`/`mysqli`/`mcrypt`
  extensions — check `laravel/` requirements) + a `mysql:5.7` service.
- All v2 configuration (DB credentials in `application/config/database.php` will not
  match the container) must be handled via **mounted override files or env tricks** —
  e.g. mount a modified copy of just the config file over the original. Document the
  exact mechanism.
- `legacy/README.md`: one-command boot instructions.
- If `php:5.6` fails (mcrypt, short tags…), try `php:5.4-apache`; timebox fallback
  hunting to a day and report if blocked.

**Acceptance criteria:**
- `docker compose -f legacy/compose.yml up` serves the app on a local port; the home
  page renders (it shows record counts; DB seeding is the next task, so zero counts or
  a DB error page is acceptable *only* if Apache/PHP/Laravel itself boots).
- `git -C ~/Eusebe status` is clean afterwards.
