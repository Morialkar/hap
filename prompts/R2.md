## R2-A — GPS field, maps, embedded gazetteer

**Context:** decision D11 (PLAN.md §2): all open-source, no Google, **no external
geocoding services — ever** (user decision). The resolver is an embedded gazetteer.

**Task (split first, then build):**
1. **GPS field type** in the registry (R1-B2 interface): stores lat/long; editor
   component = MapLibre GL map picker (drag pin, manual entry) with offline
   place-name search (GeoNames index, below).
2. **Embedded gazetteer resolver** in `packages/core`: Natural Earth admin polygons
   (public domain, 1:10m) for exact point-in-polygon country + province/state;
   GeoNames `cities1000` (CC-BY 4.0 — add attribution to the app's about screen) for
   nearest-city labels and forward name search. In-process spatial index; same
   package runs in client and is callable server-side. Locality snapshot
   {city, region, country, dataset_version, resolution_source} stored on the record;
   city label user-editable.
3. **PostGIS side table** `record_points` maintained like `record_links`; map browse
   view per database: all GPS records plotted, clustered (MapLibre), click-through
   to records; aggregation drill-down country → region → city (counts), reusing the
   C3 query AST for filters.
4. **Tiles:** MapLibre + Protomaps/OSM-derived vector tiles; document the tile
   source decision (hosted vs self-served PMTiles) with the user — offline bundles
   are R3 scope, but don't preclude them.
5. **EXIF:** strip GPS/EXIF from images on share/export by default; offer "use
   photo's location" to fill a GPS field on upload.

**AC:** gazetteer unit tests (border points, ocean points, dataset-version recorded);
map view Playwright journey; aggregation counts match a seeded fixture; EXIF both
ways tested; attribution present.

## R2-B — Visual query/report builder + exports

**Context:** P24/P25/P26 adopted with the user's expansion: a visual "query builder"
for selecting data to print/export. The C3 filter AST is the shared foundation.
The acceptance anchor: **v2's "Annexe B" must be reproducible as a shipped Report**
in the Literary Catalog template, validated against its R0-S3 golden.

**Task (split first, then build):**
1. Query AST v1 (extend C3): condition groups (AND/OR), operators per field type,
   sort, **grouping**, field selection incl. reference traversal one level deep
   (work → author.name). Server-side compiler AST → SQL with tests (golden SQL or
   result-based).
2. Visual builder UI: build/edit the AST without writing anything code-like;
   live result preview.
3. Output layouts: print-oriented layout (groups as sections, configurable fields
   per entry), CSS print styles, **PDF export** (server-rendered), **CSV export**.
   BibTeX-ish export for the Literary Catalog can be a template-level report format —
   propose in the split.
4. Reports saved per database; shipped in templates (extend R1-E1 format).
5. **Annexe B** as a Report in the Literary Catalog template: grouped by publication
   year (unknown-year group labeled "Inconnu"), entries ordered by author name, with
   pages/printer/publisher — output validated against the R0-S3 annex golden.

**AC:** annex golden reproduced; report round-trips through template export/install;
Playwright journey: build a query visually → preview → PDF and CSV download.

## R2-C — Share links

**Context:** P2 adopted. v3 is fully authenticated (D7); sharing must not weaken
that. This also finally implements what v2's dead `/share/ouvrage/:id` icon intended.

**Task (split first, then build):**
1. **Signed read-only share links** for a record, a view, or a report result:
   unguessable tokens, optional expiry, revocable (management screen listing active
   shares per database).
2. Public share renderer: read-only card/list/report display, no auth, no write
   surface, rate-limited; images served through the share scope only (no open
   enumeration); EXIF-stripped per R2-A.
3. Share UX on detail/view/report screens (copy link; optional mailto).

**AC:** feature tests: token scope (a record share exposes nothing else), expiry,
revocation; Playwright: share → open in logged-out context → renders read-only;
security notes documented in `docs/SECURITY.md`.
